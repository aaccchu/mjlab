# 自定位精度改进:距离自适应 + 高级方法(设计分析)

> 2026-06-07。回应用户两个设计问题:(1)从人类球员视角出发的**距离自适应精度**机制;
> (2)除时序外的**更高级自定位方法**(粒子滤波 MCL 等)。含可落地方案与诚实评估。

---

## 〇、一个必须先纠正的事实(影响所有后续设计)

之前我下过"三个相机杠杆全证伪、0.125m 线物理上看不见"的结论——**这个结论太绝对了,要纠正。**

渲染了 64×48→1280×960 七档机器人视角图后(`robot_view_res/`)肉眼可见:
- **64×48**:角落位姿一团糊,线消失(确实亚像素)。
- **1280×960**:同一角落位姿,中圈/多条线/球门**清晰可辨、完全可定位**。

我之前用的"标记像素占比"gate 指标会**系统性误导**:高分辨率下线变清晰,但占比不涨(草地/天空
像素同比例变多,分母一起涨)。对 CNN 而言关键是线**能否分辨边缘**,不是占百分之几。

**修正结论:0.125m 真场线在足够高分辨率下是可见、可定位的。** 之前 realspec 只到 96×72(为省显存),
分辨率不够才是 5.8m 的主因之一——不是物理不可能。**这直接支持用户"相机分辨率还可进一步提升"的判断。**

## 一、距离自适应精度机制(用户的核心想法)

### 想法复述
像人类球员:离球/球门远时,只需**粗估**自身位置(走过去就行);越靠近球、踢球越靠近球门,
对**球-机器人相对位置/深度**和**自身场上位置**的精度要求**越高**。

### 为什么这是对的(不只是直觉)
1. **匹配任务真实需求**:远处定位误差 1m 不影响"走向球"的决策;但临门一脚时,1m 误差会让球
   踢偏球门。精度需求本就是距离的函数。
2. **缓解容量竞争**:当前 `selfloc_accuracy` 是**全场均匀**的固定 std exp 核——它要求机器人在
   角落、背对球门等"地标稀少"的难位姿也达到同样精度,这些位姿恰恰最难、最耗网络容量,且对
   进球**无用**。把精度预算从"无用的远距离难位姿"挪到"有用的近球门位姿",是更聪明的容量分配。
3. **可能顺带解掉 e2e 的几何张力**:端到端"定位要全场多样性 vs 进球要近球门"的矛盾,本质是
   均匀精度要求造成的。改成"远处松、近处紧",远处的低精度不再是问题,矛盾自然缓解。

### 落地方案(三选一,按改动量递增)

**方案 A(最小改动,推荐先做):距离调制的精度奖励权重**
把 `selfloc_accuracy` 的 std 或权重做成**随"机器人到球距离"/"球到球门距离"变化**:
- 远(>3m):std 大(宽容)→ 误差 1-2m 也给高奖励。
- 近(<1m):std 小(严格)→ 必须 <0.3m 才给高奖励。
- 实现:`std_effective = std_far - (std_far - std_near) * proximity`,proximity 由 dribble
  command 已有的 `robot_to_ball` / `ball_to_goal` 距离算出(归一到 [0,1])。
- 改动:仅 `selfloc_accuracy` reward 函数加一个 distance 调制项,~15 行。无需新 obs/action。

**方案 B:对"相对位置/深度"和"绝对自定位"分别距离调制**
用户特别区分了两类精度:①球-机器人相对位置/深度 ②机器人场上绝对位置。它们由不同信号支撑
(①深度相机近距离最准;②场地线远距离才看得到多个地标)。可分别调制:
- 近球时:重罚①(深度/相对位置)误差 —— 踢准球靠这个。
- 接近球门时:重罚②(绝对自定位)误差 —— 对准球门靠这个。
- 已有 `robot_to_ball`(相对)和 `selfloc_accuracy`(绝对)两个独立信号,各加距离调制即可。

**方案 C(课程式):训练早期全场松,后期近球门紧**
把距离调制做进 curriculum,随训练推进收紧近距离精度要求——先学会粗定位+走位,再精修临门精度。

### 诚实评估
- 方案 A 改动小、风险低,**强烈建议先做** —— 它直接实现用户想法,且可能顺带缓解 e2e 几何张力。
- 风险:若调制太激进,可能让机器人"远处彻底放弃定位"导致走错方向。需保一个最低精度地板。
- 这是 reward shaping,不改变"信号是否存在"的物理事实——必须配合①的高分辨率才能让近距离真达标。

## 二、更高级的自定位方法(用户问:粒子滤波等)

当前是"CNN 直接回归位姿"(单步前馈)。更高水平的方法按递进:

### 1. 时序滤波 / 显式状态估计(已部分做:stride 叠帧)
- **现状**:6帧×stride6 被动叠帧,让 CNN 隐式利用时序。
- **升级到 RNN/GRU**:用循环网络替代叠帧,显式维护隐状态,理论上时序记忆更长更稳。中等改动
  (rl_cfg 的 actor 换 recurrent)。

### 2. 粒子滤波 / 蒙特卡洛定位(MCL)—— 用户点名的方法
- **原理**:维护 N 个"位姿假设"粒子,每步用运动模型预测、用观测(看到的线/球门与地图的匹配度)
  加权重采样。RoboCup 标准方法,能表达**多峰不确定性**(对称场地下"我可能在 A 或对称的 B")。
- **和 RL 怎么结合**(两种架构):
  - **(a) MCL 作为 obs 提供器**:在 env 里跑一个可微/不可微的 MCL,把粒子均值+方差喂给策略
    当 obs。策略不用自己学定位,专心决策。**这是最贴近"工程上能用"的方案。**
  - **(b) 可微粒子滤波(DPF)**:把 MCL 写成可微模块嵌入网络,端到端训练。前沿但实现复杂、易不稳。
- **诚实评估**:MCL 强在"对称歧义"和"不确定性表达",但它需要**观测模型**(从图像提取线/地标 →
  与地图匹配)。这一步本身就是个感知问题——要么手写线检测器(传统 CV,sim2real 又有 gap),
  要么再训一个线检测 CNN。**MCL 不是免费的,它把"端到端学定位"换成了"学感知+经典滤波"。**
  对当前纯 RL 管线是较大的架构跳变,收益主要在对称歧义场景。

### 3. 关键点/地标检测 + 几何 PnP
- CNN 检测场地关键点(角点、罚球点、中圈),已知地图 3D 坐标 → 解 PnP 直接得位姿。
- 比回归位姿更可解释、更精确(几何约束硬),也是真机常用。但需要关键点标注监督(sim 里
  可从 GT 自动生成,这是优势)。**中等改动,精度上限高,推荐作为 ①高分辨率之后的进阶。**

### 推荐优先级(投入产出比排序)
1. **①高分辨率重训**(已证图像里有信号,最直接)— 先验证 5.8m 能不能靠分辨率降到 ~2m。
2. **②距离自适应精度(方案 A)**— 小改动、直接实现用户想法、可能解几何张力。
3. **③关键点+PnP** 或 **RNN 时序** — 中等改动,精度进阶。
4. **④MCL/粒子滤波** — 架构跳变,主要解对称歧义,投入最大,建议最后。

## 三、建议的下一步实验序列(便宜→贵)

1. **高分辨率 gate 修正版**:用"边缘可分辨性"而非"像素占比"重测,确认多高分辨率够用
   (省得盲目上 1280)。零训练。
2. **realspec 高分辨率重训**:相机提到 256×192 或更高(配合降 num_envs/省显存),看纯视觉
   定位能否从 5.8m 降到亚米级。这验证"分辨率是不是主瓶颈"。
3. **加距离自适应精度(方案 A)**:在 2 的基础上加距离调制 reward,看近球门精度是否进一步提升、
   且远处放松是否缓解 e2e 几何张力。
4. 视结果再决定是否上关键点+PnP 或 MCL。
